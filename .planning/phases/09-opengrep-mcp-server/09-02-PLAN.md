<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Makefile → standalone repo | $(MAKE) -C delegates to /home/saghaulor/code/opengrep-mcp — local filesystem path, not a network fetch |
| .mcp.json → opengrep-mcp binary | Claude Code spawns binary as subprocess; binary reads SAST_ENGINE from env; SEMGREP_APP_TOKEN must come from user shell, not config file |
| opengrep-mcp → Docker daemon | Binary uses exec.Command("docker",...) with read-only mounts; Docker daemon trust boundary is in standalone, not in this integration layer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-04 | Information Disclosure | .mcp.json env block | mitigate | SEMGREP_APP_TOKEN excluded from .mcp.json; user must supply via shell env; binary reads at startup and passes to Pro container as -e flag without logging value (verified by REQ-mcp-O8 in standalone) |
| T-09-05 | Tampering | binary copy in build-opengrep-mcp | accept | Binary is built from local source under developer control; CGO_ENABLED=0 produces static binary with no dynamic linker substitution surface |
| T-09-06 | Spoofing | stdio MCP transport | accept | stdin/stdout are pipe-connected by Claude Code runtime; no network exposure; no authentication needed for local subprocess |
| T-09-SC | Tampering | npm/pip/cargo installs | accept | No package manager installs in this plan; Go build uses existing go.sum in standalone (all deps pinned) |
</threat_model>
